## 指摘
### [R1-1][Medium][bin/build-zip.sh:59-71、docs/development.md:56]
`-dirty` の判定が、中身が HEAD と違う ZIP に「クリーン」の名前を付けることがある（危ない側に外れる）。
(a) ZIP 側も HEAD 側も作業ツリーの `.distignore` で絞り、`.distignore` 自身は出荷対象外なので一覧にも出ない。`/docs` を消すと
`paidy-wc-90f223d.zip`（71 files、`docs/` の 28 ファイル入り）がクリーン名でできた。(b) `git diff` は assume-unchanged / skip-worktree の
ファイルを見ないので、変更が入ってもクリーン名。(c) HEAD 側を `git archive` で作るので export-ignore のパスが落ち、コメントの
「export-ignore はすべて `.distignore` にある」は誤り（`assets/css/*.scss`・`wordpress_org_assets`・`.gitmodules` は無い）。
その種のファイルを作業ツリーで消すと、1 ファイル少ない ZIP がクリーン名になる（今は該当する追跡ファイルなし）。
**修正方針:** HEAD 側は使い捨ての index（`read-tree` + `checkout-index`）で export-ignore を効かせずに作り、HEAD の `.distignore`
（`git show HEAD:.distignore`）で絞る。`-dirty` と一覧は 2 つのツリーの中身を `cmp` で比べて決める。
